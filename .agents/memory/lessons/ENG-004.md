# LESSON: ENG-004 — URL Authority & Port Range Validation Boundaries

- **LESSON ID:** ENG-004
- **DATE:** 2026-08-28
- **PROJECT:** pos-global
- **PHASE:** F2.02
- **CATEGORY:** Validation / Security
- **SEVERITY:** MEDIUM
- **SCOPE:** GLOBAL
- **STATUS:** ACTIVE

---

## 1. Problem
Custom URL syntax validation accepted invalid ports (e.g. `:65536`, `:0`, `:abc`, or `:` without port digits) or mishandled ports attached to paths/queries.

## 2. Root Cause
URL authority splitting logic was checking characters without parsing the authority segment (host + optional port) separately according to RFC 3986 port boundaries (`1..=65535`).

## 3. Why Checks Missed It
Basic unit tests checked valid domains (`https://example.com`) and basic malformed schemes (`ftp://`), but omitted edge cases for out-of-range port numbers (`:65536`), zero port (`:0`), and trailing colons (`:path`).

## 4. Evidence
Code review and edge-case testing identified that `validate_url_syntax("https://example.com:65536")` and `validate_url_syntax("https://example.com:")` returned `Ok(...)`.

## 5. Correct Fix
Refactored `validate_url_syntax` in `src-tauri/src/db/mod.rs` to extract the authority, separate host and port, validate host label syntax, and strictly enforce `port_u32 in 1..=65535`.

## 6. Regression Test
Unit tests in `db/mod.rs`, `brand_tests.rs`, and `manufacturer_tests.rs` testing `:65536`, `:0`, `:abc`, and trailing colon rejections.

## 7. Prevention Rule
Always validate network authorities and port boundaries strictly against standard bounds (`1..=65535`) and test all boundary conditions (0, 65535, 65536, non-digits).
