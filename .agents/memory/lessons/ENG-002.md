# LESSON: ENG-002 — SQLite Partial Unique Index Domain Error Mapping

---

- **LESSON ID:** ENG-002
- **DATE:** 2026-08-28
- **PROJECT:** pos-global
- **PHASE:** F2.02
- **CATEGORY:** Database / SQLite
- **SEVERITY:** HIGH
- **SCOPE:** PROJECT
- **STATUS:** ACTIVE

---

## 1. Problem
Tests expecting `CategoryError::DuplicateName` failed because SQLite returned a generic `SqliteFailure` constraint violation error that was not properly unpacked or mapped to the specific domain error variant.

## 2. Root Cause
The database repository layer used raw error pass-through (`map_err(CategoryError::Database)`) instead of inspecting SQLite error code / extended code 2067 (unique index violation) and mapping it to the domain error enum `CategoryError::DuplicateName`.

## 3. Why Checks Missed It
Initial tests asserted `is_err()` rather than matching the exact enum variant `matches!(err, CategoryError::DuplicateName(_))`.

## 4. Evidence
CI failure: `assertion failed: matches!(err, CategoryError::DuplicateName(_))` on `test_duplicate_active_sibling_category_rejected`.

## 5. Correct Fix
In `src-tauri/src/category/mod.rs`, intercepted SQLite constraint errors (specifically checking for index `idx_categories_name_parent_unique` or error 2067) and converted them into `CategoryError::DuplicateName(name)`.

## 6. Regression Test
`src-tauri/src/tests/category_tests.rs`: `test_duplicate_active_sibling_category_rejected` explicitly asserts `matches!(err, CategoryError::DuplicateName(_))`.

## 7. Prevention Rule
Always map underlying database constraint violations (unique, foreign key, check) to strongly-typed domain errors, and write assertions checking the exact error variant.
