## 1. Problem
File path comparisons and asset URI resolutions failed on Windows due to unnormalized backslashes (`\`) versus forward slashes (`/`).

## 2. Root Cause
Hardcoded string concatenation of file paths instead of using `std::path::PathBuf` and canonicalization.

## 3. Why Checks Missed It
Tests ran primarily on POSIX CI runners without executing Windows path separator assertions.

## 4. Evidence
Unit test path assertion failure on Windows runner with `C:\app\data` vs `C:/app/data`.

## 5. Correct Fix
Use `dunce::canonicalize` or `Path::components` to normalize path representations across platforms.

## 6. Regression Test
`test_cross_platform_path_resolution` asserting normalized path equivalence on Windows and Linux.

## 7. Prevention Rule
Never perform raw string splitting on file paths; always use standard path manipulation types.
