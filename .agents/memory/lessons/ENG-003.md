# LESSON: ENG-003 — Foreign Key Insertion Ordering in Cyclic Graph Fixtures

- **LESSON ID:** ENG-003
- **DATE:** 2026-08-28
- **PROJECT:** pos-global
- **PHASE:** F2.02
- **CATEGORY:** Testing / SQLite
- **SEVERITY:** HIGH
- **SCOPE:** GLOBAL
- **STATUS:** ACTIVE

---

## 1. Problem
Test fixture `test_category_tree_surfaces_stranded_cyclic_data` failed with SQLite FOREIGN KEY constraint failed (extended code 787) when attempting to insert node `cyc_a` referencing non-existent parent `cyc_b`.

## 2. Root Cause
In SQLite with `PRAGMA foreign_keys = ON;`, inserting a cyclic relationship directly without a parent in place violates FK constraints immediately. Setting up a stranded cycle requires inserting the parent first with a `NULL` parent, inserting the child referencing the parent, and then updating the parent's `parent_id` to point to the child.

## 3. Why Checks Missed It
The test author attempted to insert both cyclic records with pre-configured mutually circular `parent_id`s in a single step without updating.

## 4. Evidence
CI failure: `insert cyc_a -> SQLite FOREIGN KEY constraint failed (extended code 787)`.

## 5. Correct Fix
Adjusted test setup fixture to insert `cyc_a` with `parent_id = NULL`, insert `cyc_b` with `parent_id = cyc_a.id`, and then update `cyc_a`'s `parent_id = cyc_b.id`. This represents a valid historical cyclic database state under FK constraints.

## 6. Regression Test
`src-tauri/src/tests/category_tests.rs`: `test_category_tree_surfaces_stranded_cyclic_data` passes cleanly and verifies that stranded cyclic nodes are surfaced safely without infinite loops or data dropping.

## 7. Prevention Rule
When creating test fixtures for cyclic or hierarchical data under strict foreign key constraints, establish valid records first and then update pointers to create cycles.
