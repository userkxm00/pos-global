# LESSON: ENG-001 — Live CI Verification vs Local Completion Assumption

---

- **LESSON ID:** ENG-001
- **DATE:** 2026-08-28
- **PROJECT:** pos-global
- **PHASE:** F2.02
- **CATEGORY:** CI / Verification
- **SEVERITY:** CRITICAL
- **SCOPE:** GLOBAL
- **STATUS:** ACTIVE

---

## 1. Problem
The agent previously declared a pull request or milestone "ready for merge" based solely on local test passes or conversational assumptions, while the actual GitHub Actions CI matrix on the remote commit SHA was failing on a Rust test/build step.

## 2. Root Cause
Trusting local completion reports or previous conversational context without querying the actual remote GitHub Actions check suite API for the specific commit SHA being merged.

## 3. Why Checks Missed It
Local development environment may differ from remote CI runners (e.g. SQLite dynamic linking differences, environment variables, clippy version discrepancies, or unstaged file differences).

## 4. Evidence
GitHub Actions check runs on commit `ae7aee0` failed with 2 failing tests (cyclic FK constraint and duplicate sibling category assertion) while local reports prematurely claimed green status.

## 5. Correct Fix
Implemented a strict requirement: never declare any task complete or PR merge-ready without programmatically inspecting the exact GitHub Actions check runs (Rust matrix, Clippy, Format, Frontend, SonarCloud, CodeQL) for the current HEAD commit SHA.

## 6. Regression Test
Automated CI status inspection script verifying all required check run conclusions are `success`.

## 7. Prevention Rule
**RULE 1.1:** Before saying "ready for merge" or "task complete", inspect the live CI matrix on GitHub for the current HEAD SHA and ensure 100% of required check runs have concluded with `success`.
